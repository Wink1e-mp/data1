# 🤖 Lead-Bot — Telegram-бот для сбора заявок с сохранением в Google Sheets

Бот проводит пользователя по короткому опросу (**Имя → Телефон → Суть заявки**),
сохраняет заявку в Google Таблицу и уведомляет администратора в Telegram.

**Стек:** Python 3.10+, [pyTelegramBotAPI](https://github.com/eternnoir/pyTelegramBotAPI) (telebot), `requests`, `python-dotenv`.

**Как данные попадают в таблицу без JSON-ключей и Google Cloud Console:**
бот отправляет обычный HTTP POST с JSON на URL маленького скрипта
[Google Apps Script](https://www.google.com/script/start/), а тот сам дописывает
строку в вашу таблицу. Это самый простой и безопасный способ интеграции:
в коде и на сервере нет никаких привилегированных ключей — есть только адрес
веб-приложения (`GOOGLE_SCRIPT_URL`).

## Шаг 1. Получаем токен бота у @BotFather

1. Откройте Telegram и найдите официальный **@BotFather** (с синей галочкой).
   ⚠️ Не путайте с фейками — настоящий один, с галочкой.
2. Напишите команду `/newbot`.
3. BotFather спросит **имя бота** (любое, например `Мой бот заявок`).
4. Затем спросит **username** — обязательно оканчивается на `_bot`
   (например `my_leads_bot`). Если занято — придумайте другой.
5. В ответ вы получите сообщение со строкой вида:
   `123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw` — это **токен**.
6. **Сохраните токен.** Тот, кто знает токен, полностью управляет вашим ботом.
   Если токен «утёк» — сразу напишите BotFather `/revoke` и выпустите новый.

Дополнительно (по желанию): `/setdescription`, `/setabouttext`, `/setuserpic` —
описание, info и аватарка бота.

## Шаг 2. Узнаём свой chat_id (через @userinfobot)

chat_id — это числовой идентификатор вашего личного чата; на него бот
будет присылать уведомления о новых заявках.

1. Найдите в Telegram бота **@userinfobot** (или аналог @getmyid_bot).
2. Нажмите **Start** / напишите любое сообщение.
3. Бот ответит чем-то вроде `Your ID is 987654321` — заберите это число.
   Это **ваш** chat_id (ID аккаунта Telegram), он НЕ связан с токеном бота.
4. Хотите получать заявки в группу/канал? Добавьте туда бота-помощника
   вроде @getmyid_bot — он покажет отрицательный chat_id группы
   (например `-1001234567890`). Для простоты используйте личный ID.

## Шаг 3. Создаём Google Таблицу и публикуем Google Apps Script

### 3.1. Таблица
1. Зайдите на [sheets.google.com](https://sheets.google.com) под своим Google-аккаунтом.
2. Создайте новую пустую таблицу, назовите её, например, **«Заявки»**.
3. На первом листе в первую строку впишите заголовки:
   `Дата | Имя | Телефон | Суть заявки`

### 3.2. Apps Script
1. В таблице: меню **Расширения → Apps Script**. Откроется редактор кода,
   уже привязанный к этой таблице — доступ к ней у скрипта есть автоматически,
   ничего настраивать не нужно!
2. Удалите всё, что там есть, и вставьте этот код:

```javascript
// Код для редактора Google Apps Script (Расширения -> Apps Script)
function doPost(e) {
  try {
    var data = JSON.parse(e.postData.contents); // {"name":..., "phone":..., "request":...}
    var sheet = SpreadsheetApp.getActiveSpreadsheet().getActiveSheet();

    sheet.appendRow([
      new Date(),               // Дата поступления
      data.name,                // Имя
      data.phone,               // Телефон
      data.request              // Суть заявки
    ]);

    return ContentService
      .createTextOutput(JSON.stringify({ ok: true }))
      .setMimeType(ContentService.MimeType.JSON);
  } catch (err) {
    return ContentService
      .createTextOutput(JSON.stringify({ ok: false, error: String(err) }))
      .setMimeType(ContentService.MimeType.JSON);
  }
}
```

3. Сохраните проект (💾, назовите его, например `LeadSheet`).
4. **Deploy → New deployment**.
5. Тип (шестерёнка ⚙️ «Select type») → **Web app**.
6. Заполните:
   - *Execute as*: **Me** (ваш аккаунт);
   - *Who has access*: **Anyone** (обязательно! иначе бот получит 403).
     При этом скрипт умеет только добавлять строки в эту таблицу —
     это нормальная модель доверия для формы заявок.
7. Нажмите **Deploy**. Google попросит авторизовать скрипт от вашего имени:
   *Authorize* → выберите аккаунт → (если предупреждение «Unverified app»)
   **Advanced → Go to project (unsafe)** → *Allow*. Пугаться не стоит —
   это ваш собственный скрипт, просто он не верифицирован Google.
8. Скопируйте **Web app URL** — он выглядит как
   `https://script.google.com/macros/s/AKfycb.../exec` — это и есть значение
   для `GOOGLE_SCRIPT_URL`.

⚠️ Важно про обновления: после каждого изменения кода скрипта нужно делать
**Deploy → Manage deployments → ✏️ Edit → Version: New version → Deploy**
(старый URL при этом сохраняется). Если заменили скрипт и бот начал ошибаться —
скорее всего, вы забыли перезалить версию.

### 3.3. Быстрая проверка URL (можно сделать прямо сейчас)

```bash
curl -sL -X POST "https://script.google.com/macros/s/XXXX/exec" \
  -H "Content-Type: application/json" \
  -d '{"name":"Тест","phone":"+79990000000","request":"Проверка таблицы"}'
```

Если в ответ видите `{"ok":true}` и в таблице появилась строка — всё работает. ✅

## Шаг 5. Настраиваем секреты (.env)

```bash
cp .env.example .env
nano .env        # или откройте .env в любом редакторе
```

Заполните:

```ini
TELEGRAM_BOT_TOKEN=123456789:AA...        # токен из Шага 1
ADMIN_CHAT_ID=987654321                   # ваш chat_id из Шага 2
GOOGLE_SCRIPT_URL=https://script.google.com/macros/s/AKfycb.../exec   # URL из Шага 3
```

Правила безопасности:
- `.env` **никогда** не коммитим в git (он уже в `.gitignore`);
- не копируйте токен в скриншоты, чаты и код;
- в публичный репозиторий можно класть только `.env.example` (пустой шаблон).

## Шаг 6. Запускаем бота

```bash
python bot.py
```

В консоли (и в `bot.log`) появятся сообщения о запуске. Теперь:

1. Найдите своего бота в Telegram (`@your_username_bot`) и напишите `/start`;
2. последовательно ответьте на 3 вопроса;
3. проверьте: в таблице появилась строка, вам (админу) пришло уведомление 🎉.

Остановить бота: `Ctrl+C`.

## 🧯 Частые проблемы (Troubleshooting)

| Симптом | Причина и решение |
|---|---|
| 401 Unauthorized | Неверный токен. Проверьте `TELEGRAM_BOT_TOKEN`, при необходимости `/revoke` + новый токен. |
| Бот молчит | Не запущен `python bot.py`, либо зависло состояние диалога — перезапустите и напишите `/start`. |
| Заявка не сохраняется, в логе HTTP 403/404 | Apps Script: доступ не **Anyone**, либо после правки кода не создана **New version** deployment. |
| В логе «Apps Script вернул не-JSON» | Вы скопировали URL редактирования (`/edit`), нужен URL, оканчивающийся на **/exec**. |
| `Bad Request: chat not found` при уведомлении админа | Неверный `ADMIN_CHAT_ID`. Заново узнайте его через @userinfobot. |
| Ошибка «Переменная окружения ... не задана» | Нет файла `.env` или он в другой папке — положите рядом с `bot.py`. |
| Строки пишутся не в тот лист | `getActiveSheet()` берёт первый лист. Нужен другой — замените в скрипте на `getSheetByName("Заявки")`. |

## 🔐 Безопасность: что уже сделано и что можно улучшить

Уже в коде:
- все секреты только из `.env`, в git не попадают (`.gitignore`);
- санитизация ввода: лимиты длины, удаление управляющих символов, защита от
  formula injection (`=`, `+`, `-`, `@` в начале строки);
- валидация имени и телефона (regex), чтобы в таблицу не попадал мусор;
- `try/except` вокруг Telegram API и HTTP-запросов — бот не падает;
- обязательные таймауты сетевых запросов;
- логирование в `bot.log` без записи токена.

Идеи для развития (как студенту ИБ — будет что показать):
- rate-limiting (не чаще N заявок в минуту) и «чёрный список» по user_id;
- перенести FSM-состояния в Redis — диалоги переживут рестарт;
- HTTPS-webhook вместо polling + секретный токен в URL webhook;
- маскирование телефонов в логах (это персональные данные!).
